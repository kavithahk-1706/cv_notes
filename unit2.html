11. Define the Mat structure in OpenCV and list its important properties.

cv::Mat (short for Matrix) is OpenCV’s fundamental container for images and N-dimensional numeric arrays. In Python the same role is played by a NumPy ndarray, which OpenCV wraps transparently. Every image, mask, convolution kernel, histogram or intermediate processing result is stored in a Mat. The structure has two parts: a small header that describes the shape, type and memory layout of the array, and a large data block that holds the actual pixel values in contiguous memory.

The separation of header and data is a deliberate design choice that enables efficient memory management. When an image is passed to a function or assigned to a new variable, only the lightweight header is copied while the heavy pixel data stays in place. This avoids expensive deep copies during normal operations and is one of the reasons OpenCV achieves real-time performance.

Important properties

PropertyMeaning
rows, colsHeight and width of the image (number of rows and columns)
dimsNumber of dimensions (2 for a normal image, 3 or more for volumes)
channels()Values per pixel: 1 for gray, 3 for BGR colour, 4 with alpha
depth() / type()Data type of each value, such as CV_8U (8-bit unsigned), CV_32F (float); type includes the channels, e.g. CV_8UC3
step[0], step[1]Byte stride: bytes from one row to the next (including padding), and from one element to the next
dataPointer to the first byte of the pixel data
size(), total(), empty(), isContinuous()Image size, number of elements, whether the array is empty, and whether rows are stored without gaps

Memory management

  • Reference counting: assignment and function arguments copy only the header (shallow copy), so both headers share one data block. An internal counter tracks how many headers point to the data, and the block is freed automatically when the last header disappears. This eliminates manual memory management and prevents leaks in complex pipelines.
  • Deep copy: clone() or copyTo() creates fully independent pixel data. Use a deep copy whenever the downstream operation will modify pixels and the original must stay untouched, for example when building a before-and-after comparison or feeding two different filters from the same source frame.
  • Layout: rows are stored one after another (row-major) and the channels of one pixel are adjacent (interleaved BGR order). This layout means sequential access along a row hits consecutive cache lines, which is why row-wise traversal is the fastest pattern for most operations.
\[ \text{address}(y,x)=\text{data}+y\cdot \text{step}[0]+x\cdot \text{step}[1] \]

Here \(\text{data}\) is the address of the first byte, \(y\) and \(x\) are the row and column of the pixel, step[0] is the bytes per row and step[1] the bytes per element. The formula shows how OpenCV finds any pixel in one multiplication and addition. Because of step[0], a cropped region (ROI) can share the memory of the parent image without copying.

cv::Mat A = cv::imread("img.jpg");   // A owns the pixel data
cv::Mat B = A;                       // shallow copy: B shares A's data (only the header is copied)
cv::Mat C = A.clone();               // deep copy: C has its own data
cv::Mat roi = A(cv::Rect(10, 10, 100, 100));  // ROI header pointing inside A, no copy
std::cout << A.rows << " " << A.cols << " " << A.channels() << " " << A.type();  // inspect the header

12. List any three image traversal methods and state the purpose of lookup table-based intensity transformation.

Image traversal means the systematic order in which an algorithm visits every pixel of an image. Choosing the right traversal is not just a coding convention — it directly affects execution speed through memory access patterns, determines how well compressed data groups together, and shapes the kind of spatial analysis that is possible. Modern CPUs load data in cache lines of 64 bytes, so an access pattern that follows the physical memory layout avoids costly cache misses and can be several times faster than a random pattern on the same image.

  1. Raster (row-major) scan: visits pixels row by row, left to right, top to bottom. Because a Mat stores pixel data in the same row-major order, raster scanning reads consecutive memory addresses and achieves the best CPU cache behaviour. It is the default pattern for convolution filters, histogram computation, display refresh and video frame scanning. Nearly every OpenCV function that iterates over an image uses raster order internally.
  2. Boustrophedon (zigzag row) scan: the direction alternates on every row — left to right on even rows, right to left on odd rows — mimicking how an ox ploughs a field (the Greek origin of the name). This pattern eliminates the long pointer jump that raster scanning makes at the end of each row back to the start of the next. It is widely used in flatbed scanners, inkjet printers and robotic path planning for area coverage, where the physical head can simply reverse direction instead of repositioning.
  3. Zigzag diagonal scan (JPEG): visits the diagonals of an 8×8 DCT coefficient block from the low-frequency corner to the high-frequency corner. After quantisation most high-frequency coefficients become zero, so the zigzag ordering groups these zeros together at the tail of the sequence. This makes run-length encoding and Huffman coding highly efficient and is the reason JPEG achieves good compression ratios on natural images.

Beyond these three, other traversal methods include spiral scan (used in some block-matching algorithms), space-filling curves such as Z-order and Hilbert curves that preserve 2D locality for memory mapping and database indexing, quadtree recursive subdivision, and region-based traversals like flood fill and contour tracing that follow connected components rather than a fixed geometric pattern.

Lookup-table (LUT) intensity transformation: purpose

A point operation changes each pixel based solely on its own value, for example applying the gamma function output \(= 255 \times (input/255)^{\gamma}\). Evaluating such a mathematical function for every pixel in a high-resolution image is computationally expensive. However, for an 8-bit image there are only 256 possible input values (0–255), so the function can be evaluated just 256 times and the results stored in a one-dimensional array called a lookup table. After building the table, every pixel is transformed by a single array read — fetch lut[pixel_value] — instead of repeating the floating-point calculation.

The performance gain is dramatic. A 1080p colour frame has over two million pixels and three channels each, meaning roughly six million function evaluations per frame. At 30 fps that becomes about 180 million evaluations per second. A LUT reduces this to 256 evaluations plus the same number of trivial table reads, which is orders of magnitude faster. LUTs are therefore the standard technique for negative transformation, gamma correction, logarithmic compression, thresholding, contrast stretching and pseudocolour mapping in real-time systems.

import cv2, numpy as np
img = cv2.imread("photo.jpg", cv2.IMREAD_GRAYSCALE)

gamma = 0.5                                              # <1 brightens, >1 darkens
lut = np.array([255 * (i / 255) ** gamma for i in range(256)],  # compute the formula only 256 times
               dtype="uint8")                            # table index = input value, entry = output value
out = cv2.LUT(img, lut)                                  # apply: out[y,x] = lut[img[y,x]] for every pixel

13. Explain pixel-level access in OpenCV and discuss its importance in image processing.

Pixel-level access means reading or writing the value of an individual pixel (or a small group of pixels) through its row and column index. Since an image in OpenCV is stored as a matrix, the pixel at row \(y\) and column \(x\) is simply the matrix element at that position. The coordinate origin is the top-left corner of the image, with rows numbered downwards and columns numbered to the right — the same convention used by displays and cameras.

Understanding pixel-level access is fundamental because every image processing operation ultimately reduces to reading pixel values, performing some computation, and writing new values back. Whether it is a simple brightness adjustment or a complex neural network inference, the data path always begins and ends at individual pixels stored in the matrix.

Ways of access

  • Python (NumPy): img[y, x] returns the intensity of a grayscale pixel, or a [B, G, R] array for a colour pixel; assigning to it changes the pixel. NumPy slices such as img[0:50, 0:50] give a whole region as a view without copying data, making region-of-interest extraction very efficient.
  • C++ at<>: img.at<uchar>(y, x) for grayscale and img.at<cv::Vec3b>(y, x) for colour; clean and type-safe, but each call recomputes the row address from scratch, so it is slower inside tight loops compared to pointer access.
  • C++ pointer: img.ptr<uchar>(y) returns a pointer to the start of row \(y\), so iterating across columns uses pointer arithmetic and avoids repeated address computation. This is the fastest method in C++ and is preferred in performance-critical code such as real-time video processing.
  • Iterator: MatIterator_ visits every pixel sequentially without explicit index management. It abstracts away the memory layout and is useful when the algorithm does not depend on spatial position.
import cv2
img = cv2.imread("photo.jpg")            # colour image, shape (h, w, 3)

p = img[100, 50]                         # row 100, column 50 -> array([B, G, R])
print(p, p[2])                           # p[2] is the red value (BGR order)

img[100, 50] = (255, 255, 255)           # write: make one pixel white
img[20:60, 30:90] = (0, 0, 0)            # write: black rectangle (rows 20-59, cols 30-89)
img[:, :, 2] = 0                         # remove the red channel (channel index 2)

gray = cv2.imread("photo.jpg", 0)        # 0 = IMREAD_GRAYSCALE
print(gray[100, 50])                     # a single number 0-255

Importance in image processing

  • Foundation of every algorithm: filtering, thresholding, edge detection and colour conversion all read neighbouring pixels and compute new values. Without efficient pixel access these operations would be impractical at real-time frame rates.
  • Custom operations: many real-world tasks require operations that no built-in function provides, such as applying a non-standard mask, painting a region based on domain logic, or drawing application-specific overlays. Pixel access makes these possible.
  • Region-of-interest (ROI) processing: cropping, replacing part of an image, inserting a watermark or extracting a sub-region for further analysis all depend on addressed pixel access. Similarly, interactive applications read pixel values at a mouse click location to identify colours or trigger actions.
  • Debugging and validation: inspecting actual pixel values helps verify that an algorithm is producing correct intermediate results, which is essential during development of new processing pipelines.

Caution. Looping over pixels in Python is very slow; where possible use vectorised NumPy expressions or OpenCV functions (cv2.add, cv2.LUT, cv2.threshold), and use pointer access in C++ for speed. Remember that the index order is [row, column] = [y, x], and that uint8 arithmetic wraps around (250 + 10 gives 4) unless cv2.add is used.

14. Explain mask operations and image blending with suitable examples.

A mask operation (also called spatial filtering or convolution) recalculates the value of every pixel by combining its own value with those of its neighbours, using a small matrix of weights called a mask or kernel (commonly 3×3 or 5×5). The kernel is centred over each pixel in turn; corresponding image and kernel values are multiplied element-wise, the products are summed, and the result becomes the new value of the centre pixel. This sliding-window mechanism is the single most important building block in image processing — blurring, sharpening, edge detection and embossing are all achieved by choosing different kernel weights.

\[ I'(i,j)=5\,I(i,j)-\big[I(i-1,j)+I(i+1,j)+I(i,j-1)+I(i,j+1)\big] \]

This is the sharpening mask of the figure. \(I(i,j)\) is the old value of the pixel at row \(i\), column \(j\); the four terms in brackets are its upper, lower, left and right neighbours; \(I'(i,j)\) is the new value. If the centre is the same as its neighbours, the result equals the old value; if it is brighter than them, the difference is amplified. So the formula increases local contrast and makes edges look crisp. The weights add up to 1, which keeps the overall brightness unchanged. A blur mask has all weights positive and also summing to 1; edge masks (Sobel, Prewitt) sum to 0, so flat areas become black.

import cv2, numpy as np
img = cv2.imread("photo.jpg", cv2.IMREAD_GRAYSCALE)

kernel = np.array([[ 0, -1,  0],           # sharpening mask: centre 5, four neighbours -1
                   [-1,  5, -1],
                   [ 0, -1,  0]], dtype=np.float32)
sharp = cv2.filter2D(img, -1, kernel)      # -1 = output depth same as input; slides the kernel over every pixel

blur = cv2.blur(img, (3, 3))               # box mask: every weight 1/9, i.e. a 3x3 average

The word mask is also used in a different sense for a binary mask, which is a single-channel image of 0s and 255s (or 0s and 1s) that selects a region. Passing such a mask to cv2.bitwise_and(img, img, mask=m) keeps only the pixels where the mask is non-zero, effectively cutting out an arbitrary shape from the image. Binary masks are essential for tasks such as background removal, selective filtering and object compositing.

Image blending

Blending combines two images of the same size into one by computing a weighted sum of their pixel values at every location. Unlike a hard overlay where one image simply replaces the other, blending produces a smooth transition that preserves visible content from both sources.

\[ \text{dst}=\alpha\cdot \text{img}_1+\beta\cdot \text{img}_2+\gamma \]

Here \(\text{img}_1\) and \(\text{img}_2\) are the two input images; \(\alpha\) and \(\beta\) are their weights, normally between 0 and 1 and chosen so that \(\alpha+\beta=1\) (otherwise the result is too bright or too dark); \(\gamma\) is a constant added to every pixel (a brightness offset, usually 0). With \(\alpha=0.7,\ \beta=0.3\) the first image dominates. Using a changing \(\alpha\) over time gives a cross-fade.

a = cv2.imread("a.jpg")
b = cv2.imread("b.jpg")
b = cv2.resize(b, (a.shape[1], a.shape[0]))        # images must have the same size and type
mix = cv2.addWeighted(a, 0.7, b, 0.3, 0)           # 0.7*a + 0.3*b + 0 (gamma); result is saturated to 0-255

Applications: blending is used in panorama stitching to merge overlapping images seamlessly, in video editing for fade transitions between clips, in watermarking to embed a translucent logo, in augmented reality to overlay virtual objects onto real scenes, and in HDR imaging to combine multiple exposures into a single image with greater dynamic range. Laplacian pyramid blending is an advanced variant that blends at multiple scales, avoiding the ghosting artefacts that simple global blending can produce when objects differ between the two images.

15. Explain frequency-domain processing using the Discrete Fourier Transform (DFT).

Every image can be understood from two complementary perspectives. In the spatial domain it is a grid of brightness values arranged by position — what we see when we look at the pixel matrix directly. In the frequency domain the same image is described as a weighted sum of sine and cosine waves of different frequencies, directions and amplitudes. The Discrete Fourier Transform (DFT) converts an image from the spatial to the frequency domain, and the inverse DFT converts it back with no loss of information. Low frequencies represent slow, gradual changes such as overall brightness and broad shapes, while high frequencies capture rapid changes such as edges, fine texture and noise.

Frequency-domain analysis is powerful because certain operations that are complex in the spatial domain become trivially simple when expressed in terms of frequencies. Removing noise at a specific frequency, for instance, is just zeroing out the corresponding coefficient — something that would require a carefully designed spatial filter to approximate.

\[ F(u,v)=\sum_{x=0}^{M-1}\sum_{y=0}^{N-1} f(x,y)\,e^{-j2\pi\left(\frac{ux}{M}+\frac{vy}{N}\right)} \]

Here \(f(x,y)\) is the pixel brightness at column \(x\), row \(y\); \(M\) and \(N\) are the image width and height; \((u,v)\) is the frequency being tested (horizontal and vertical); and \(e^{-j2\pi(\cdots)}\) is a complex wave of that frequency. For each \((u,v)\), every pixel is multiplied by the wave and the results are added, so \(F(u,v)\) is large when the image contains that pattern. It is a complex number: its magnitude tells how strong the frequency is, and its phase tells where the pattern lies. The fast algorithm used in practice is the FFT.

Frequency-domain filtering pipeline

The raw DFT output places the zero-frequency (DC) component at the corners, which is unintuitive for visual inspection. The fftshift operation rearranges the quadrants so that low frequencies lie at the centre of the spectrum image and high frequencies at the edges. After the shift, filtering is a simple element-wise multiplication of the spectrum by a mask, and the inverse DFT reconstructs the filtered image in the spatial domain.

A low-pass mask keeps only the centre region, suppressing high frequencies and producing a blurred result. A high-pass mask blocks the centre, retaining edges and fine detail while removing smooth gradients. A notch mask zeros out isolated frequency spikes, which is the standard technique for removing periodic noise such as a regular stripe pattern from a scanner. Using a smooth Gaussian mask instead of a hard circular cut-off avoids an artefact known as ringing, where sharp transitions in the frequency domain create oscillating bands in the spatial output. A smaller cut-off radius on a low-pass mask keeps fewer frequencies, resulting in stronger blurring.

import cv2, numpy as np
img = cv2.imread("photo.jpg", cv2.IMREAD_GRAYSCALE)

dft = cv2.dft(np.float32(img), flags=cv2.DFT_COMPLEX_OUTPUT)   # forward DFT; output has 2 channels (real, imaginary)
dft = np.fft.fftshift(dft)                                     # move low frequencies (DC) to the centre

mag = 20 * np.log(cv2.magnitude(dft[:, :, 0], dft[:, :, 1]) + 1)  # magnitude spectrum; log makes it visible

rows, cols = img.shape
mask = np.zeros((rows, cols, 2), np.float32)                   # low-pass mask: zeros everywhere...
cv2.circle(mask, (cols // 2, rows // 2), 30, (1, 1), -1)       # ...except a filled circle of radius 30 at the centre

filtered = dft * mask                                          # filtering = simple multiplication
back = cv2.idft(np.fft.ifftshift(filtered))                    # undo the shift, then inverse DFT
result = cv2.magnitude(back[:, :, 0], back[:, :, 1])           # real image again (blurred)

Applications: frequency-domain processing is used for removal of periodic noise from scanned documents, controlled blurring and sharpening with precise frequency cut-offs, image compression (JPEG works by quantising DCT coefficients, effectively discarding less perceptible high-frequency information), and texture classification where the frequency signature of a pattern is more discriminative than raw pixel values.

16. Implement an OpenCV operation to access and modify selected pixel values using the Mat structure.

The aim is to read selected pixels of a Mat and change them programmatically. Pixel modification falls into three categories: accessing a single pixel by its row and column coordinates, modifying an entire rectangular region (ROI — region of interest) in one operation, and changing all pixels that satisfy a condition using a boolean mask. The C++ interface provides at<> for safe element access and Rect for region selection, while the Python interface leverages NumPy array indexing to achieve the same operations with more concise syntax.

This kind of direct pixel manipulation is the basis for operations like drawing bounding boxes around detected objects, anonymising faces by filling regions with a solid colour, applying selective colour corrections, and implementing custom segmentation masks. Understanding both the C++ and Python approaches is important because C++ is used in production systems requiring maximum speed, while Python is preferred for prototyping and research.

C++ (cv::Mat)

Steps in words

  1. Load the image and check it is not empty.
  2. Choose the pixel(s): by one coordinate (row, column), or by a region (a slice).
  3. Read the pixel. In C++, img.at<Vec3b>(y, x) returns the three BGR values of a colour pixel (at<uchar> for gray). In Python, img[y, x] returns the array of three values.
  4. Write the new value to the same expression, then display or save the image.

Points to remember: the first index is the row (y), the second the column (x); the channel order is B, G, R; the type in at<> must match the image type or the values will be wrong; values are uchar/uint8, so arithmetic must be clipped to 0–255 (use saturate_cast in C++).

#include <opencv2/opencv.hpp>
using namespace cv;

int main() {
    Mat img = imread("photo.jpg");                       // 8-bit, 3-channel BGR Mat
    if (img.empty()) return -1;                          // always test that loading worked

    Vec3b p = img.at<Vec3b>(50, 80);                     // READ pixel at row 50, col 80: Vec3b = {B, G, R}
    std::cout << (int)p[0] << " " << (int)p[1] << " " << (int)p[2] << std::endl;

    img.at<Vec3b>(50, 80) = Vec3b(0, 0, 255);            // MODIFY one pixel: set it red (B=0, G=0, R=255)

    Mat roi = img(Rect(100, 100, 60, 40));               // ROI: Rect(x, y, width, height); shares img's data
    roi.setTo(Scalar(255, 0, 0));                        // paint the whole region blue; this also changes img

    for (int y = 0; y < img.rows; y++) {                 // MODIFY by condition: scan every row...
        uchar* row = img.ptr<uchar>(y);                  // ...with a pointer to the start of that row (fast)
        for (int x = 0; x < img.cols * img.channels(); x++)  // channels are interleaved, so cols*channels values
            if (row[x] > 200) row[x] = 255;              // push very bright values to 255
    }
    imwrite("modified.jpg", img);
    return 0;
}

Python (same operations)

import cv2
img = cv2.imread("photo.jpg")

print(img[50, 80])                 # read pixel [B G R] at row 50, column 80
img[50, 80] = (0, 0, 255)          # set that pixel to red

roi = img[100:140, 100:160]        # ROI slice [y1:y2, x1:x2]: a view of img, not a copy
roi[:] = (255, 0, 0)               # paint the region blue; img changes too

img[img > 200] = 255               # condition on all values at once (vectorised, fast)

Explanation

  • at<Vec3b>(row, col) accesses one colour pixel; Vec3b holds three uchar values in B, G, R order. For a gray image use at<uchar>.
  • The ROI is only a new header over the same data (see Q11), so editing it edits the original image; use clone() if an independent copy is needed.
  • ptr<uchar>(y) gives a pointer to row y, which is the fastest way to scan in C++; at<> is easier but slower because each call recalculates the address.
  • Index order is (row, col) = (y, x) for at, but Rect and drawing functions use (x, y).

Modifying selected pixels: a single pixel is changed through its coordinates, a whole region by slicing (img[50:100, 80:160] = (0, 0, 255) paints a red rectangle), and pixels that satisfy a condition can be selected with a boolean mask (img[img > 200] = 255). In Python, explicit for-loops over every pixel are extremely slow because each iteration crosses the Python–C boundary; NumPy array slicing and boolean masks delegate the loop to optimised C code, making them hundreds of times faster for the same operation.

Performance consideration: in C++, the ptr<> method is preferred inside tight loops because it computes the row address once and then accesses columns through simple pointer arithmetic. The at<> method recalculates the full address on every call and includes a bounds check in debug mode, which adds overhead. For bulk operations in Python, always prefer vectorised expressions over pixel-by-pixel loops.

17. Demonstrate how brightness and contrast of an image can be adjusted using OpenCV.

Brightness and contrast are the two most fundamental visual properties of an image that users and algorithms routinely need to adjust. Both are controlled by a single linear (point) transformation applied independently to every pixel, making the operation extremely fast since no neighbourhood information is needed:

\[ g(x,y)=\alpha\, f(x,y)+\beta \]

Here \(f(x,y)\) is the input pixel value, \(g(x,y)\) is the output value, \(\alpha\) (gain) controls contrast and \(\beta\) (bias) controls brightness. The gain \(\alpha\) acts as a multiplier: with \(\alpha>1\) the differences between dark and bright pixels are stretched, increasing contrast and making the image appear more vivid. With \(0<\alpha<1\) those differences are compressed, reducing contrast and giving a flat, washed-out appearance. The bias \(\beta\) is an additive offset: a positive value shifts all pixels upward on the intensity scale (brighter), while a negative value shifts them downward (darker). Results that exceed 255 or fall below 0 are clipped (saturated) to the valid 8-bit range.

The graph below illustrates these effects. The identity line (\(\alpha=1, \beta=0\)) leaves every pixel unchanged. The steeper line (\(\alpha=1.5, \beta=30\)) amplifies differences and lifts the baseline, but saturates at 255 for input values above approximately 150, destroying highlight detail. This saturation trade-off is why practical values of \(\alpha\) rarely exceed 2.0 and \(\beta\) is typically kept between −100 and +100.

Effect of the two parameters

ChangeEffect on the image
\(\beta>0\) (e.g. +50)Brighter: every pixel is shifted up; histogram moves right
\(\beta<0\)Darker: histogram moves left
\(\alpha>1\) (e.g. 1.5)Higher contrast: the difference between dark and bright pixels is stretched
\(0<\alpha<1\)Lower contrast: the intensities are squeezed together, image looks flat

Results above 255 or below 0 are saturated (clipped to the valid range); this is why a large \(\alpha\) or \(\beta\) can cause bright areas to turn pure white and lose all detail — a problem known as highlight clipping. Similarly, dark regions can be crushed to pure black. OpenCV handles this clipping automatically in convertScaleAbs (C++) and cv2.convertScaleAbs (Python), and through the saturate_cast function in custom C++ loops. If you perform the computation manually using NumPy, you must convert to a floating-point type first, apply the formula, and then clip with np.clip before converting back to uint8, because raw uint8 arithmetic wraps around silently (e.g. 250 + 10 gives 4 instead of 255).

Steps

  1. Load the image.
  2. Choose \(\alpha\) (contrast) and \(\beta\) (brightness).
  3. Apply \(g=\alpha f+\beta\) to every pixel, with saturation.
  4. Compare original and result, and adjust the values.
import cv2, numpy as np
img = cv2.imread("photo.jpg")

alpha = 1.5                                         # contrast: 1.0 = unchanged, >1 more, <1 less (typical 0.5-3)
beta  = 30                                          # brightness offset: positive = brighter (typical -100..+100)

adj = cv2.convertScaleAbs(img, alpha=alpha, beta=beta)   # computes |alpha*img + beta|, clips to 0-255, returns uint8
# equivalent with addWeighted: add a black image with gamma = beta
adj2 = cv2.addWeighted(img, alpha, np.zeros_like(img), 0, beta)

# manual NumPy version: convert to float first, otherwise uint8 overflows silently
manual = np.clip(alpha * img.astype(np.float32) + beta, 0, 255).astype(np.uint8)

cv2.imshow("original | adjusted", np.hstack([img, adj]))  # side by side comparison
cv2.waitKey(0)

Remember: alpha = contrast (multiply), beta = brightness (add). Use convertScaleAbs in practice because it clips and converts safely. Too large \(\alpha\) or \(\beta\) destroys detail in bright or dark regions (saturation), so values are tuned by looking at the result or the histogram. For automatic enhancement, histogram equalization (Q29) is used.

Alternatives and when to use them: gamma correction applies a non-linear curve \(g = 255 \times (f/255)^{\gamma}\) that selectively brightens shadows without blowing out highlights, making it ideal for underexposed photographs. Histogram equalization (covered in later units) redistributes pixel intensities automatically so the full 0–255 range is used, which is especially effective for low-contrast medical or satellite images. In practice, the linear method shown here is used for quick manual adjustment, while gamma and histogram equalization handle cases where a simple shift and scale are not enough.

18. Compare and analyze different image traversal methods with respect to their processing efficiency.

Processing efficiency of image traversal depends on two interacting factors: the order in which pixels are visited (which determines how well the access pattern exploits the CPU cache hierarchy), and the method of access the program uses to read or write each pixel (which determines the per-pixel overhead). Choosing the right combination can make the difference between an algorithm that runs in real time and one that is unusably slow.

1. Effect of traversal order

A Mat stores its pixel data row after row in contiguous memory. Visiting pixels in raster (row-major) order therefore reads consecutive memory addresses, which makes full use of the CPU cache — when a cache line of 64 bytes is loaded, every byte in it is used before the next load. Visiting by columns, in contrast, jumps one whole row (step[0] bytes) between neighbouring accesses, causing frequent cache misses and making the traversal several times slower on large images.

Boustrophedon order alternates direction on each row. Its cache behaviour is nearly identical to raster because it still accesses within the same row, but it avoids the long repositioning jump at the end of each line, which benefits hardware like print heads and robotic scanners. Z-order and Hilbert space-filling curves keep both horizontal and vertical neighbours close in the linear address sequence, which improves locality for block-based GPU processing and database tiling. Hilbert curves have no large jumps at all but require more index arithmetic. Zigzag diagonal scanning is designed for JPEG compression efficiency rather than raw speed. Region-based traversals such as flood fill and contour tracing depend on image content, so their running time is data-dependent and hard to predict in advance.

Conclusion. For best efficiency: visit memory in row-major order to maximise cache hits, avoid per-pixel function-call overhead by using pointers or iterators in C++, use a LUT for any per-value transformation since it replaces repeated floating-point computation with a single table read, and never write pixel-level for-loops in Python — always use NumPy vectorised operations or OpenCV built-in functions that execute the loop in compiled C/C++ code. When even these are not fast enough, GPU acceleration through CUDA or OpenCL can process all pixels in parallel, achieving orders-of-magnitude speedup for large images.

19. An image looks satisfactory in the spatial domain but contains unwanted periodic patterns. Analyze why frequency-domain processing using DFT may be more appropriate.

An image can look acceptable overall yet contain a regular repeating pattern such as horizontal stripes, a fine mesh or diagonal scan lines. Such patterns commonly arise when scanning a printed halftone photograph, from electromagnetic interference in a sensor, from aliasing in under-sampled video, or from mechanical vibration in the camera. This is called periodic noise, and it is one of the few noise types that is fundamentally easier to handle in the frequency domain than in the spatial domain. The key reason is that a periodic pattern, by definition, has a well-defined frequency and direction, which maps to a compact, identifiable signature in the DFT spectrum.

  • The pattern is concentrated in the spectrum. A regular pattern repeats with one fixed frequency and direction, so in the DFT it appears as a few isolated bright spikes (symmetric around the centre), while in the spatial domain it is spread over the whole image and mixed with real detail.
  • Spatial filters cannot separate it from detail. A blur or median filter reduces noise by averaging neighbouring pixels, which also removes real edges and texture; it would soften the picture and may still leave the stripes visible. A mask small enough to keep detail does not remove a low-frequency pattern.
  • A notch filter targets only the noise. In the frequency domain the spikes can be located and set to zero (or masked by small notches) while all other frequencies stay unchanged. The inverse DFT then returns the image without the pattern and with its sharpness preserved.
  • Control and efficiency. The cut-off, notch size and smoothness are easy to tune, and filtering becomes a simple multiplication by a mask, which is fast when the FFT is used (large spatial kernels would be slow).

Procedure: compute the DFT and shift it so low frequencies are centred → display the log-magnitude spectrum to make the spikes visible → identify the isolated bright spikes (ignoring the central DC component, which represents overall average brightness) → multiply by a mask that is 0 at and around each spike and 1 everywhere else (using a Gaussian taper rather than a hard circle avoids ringing artefacts) → undo the shift and apply the inverse DFT to recover the cleaned image.

In summary, periodic noise is simple and concentrated in the frequency domain — just a few spikes — but complex and spread everywhere in the spatial domain. Frequency-domain filtering can surgically remove those spikes without touching anything else, while spatial filtering would inevitably blur or distort the image content along with the noise. This makes DFT-based processing the standard approach for periodic noise removal in fields such as document scanning, satellite imaging and industrial inspection.

20. Evaluate the suitability of XML and YAML for storing and retrieving configuration data in OpenCV applications. Justify your choice.

Computer vision applications routinely produce and consume non-image data: camera intrinsic and extrinsic matrices from calibration, trained classifier parameters, detection thresholds, region-of-interest coordinates and file paths. This data must be stored persistently so that a pipeline configured once can be reloaded without re-running expensive calibration or training steps. OpenCV’s FileStorage class provides a unified API for reading and writing such data in XML, YAML and JSON formats. The format is selected entirely by the file extension (.xml, .yml/.yaml, .json), and the same code works unchanged regardless of which format is chosen. Both XML and YAML are human-readable, hierarchical, cross-platform and natively support Mat objects, scalars, strings and sequences.

import cv2, numpy as np

fs = cv2.FileStorage("config.yml", cv2.FILE_STORAGE_WRITE)  # open for writing; extension chooses YAML (use .xml for XML)
fs.write("camera_matrix", np.eye(3))                        # store a Mat/array under a key
fs.write("threshold", 127)                                  # store a number
fs.write("model_name", "face_v1")                           # store a string
fs.release()                                                # always close: flushes data to disk

fs = cv2.FileStorage("config.yml", cv2.FILE_STORAGE_READ)   # open for reading
K = fs.getNode("camera_matrix").mat()                       # read back the matrix
t = int(fs.getNode("threshold").real())                     # numbers come back as nodes: convert them
fs.release()

Evaluation and choice

Since the OpenCV API is identical for both formats, the decision comes down to the people and tools that will interact with the file. For configuration data of an OpenCV application — thresholds, paths, camera parameters, calibration results — YAML is the stronger choice: it is concise, easy for developers to read and edit by hand without any special tooling, supports inline comments for documenting parameter choices, and is the de facto standard for configuration in modern DevOps and ML workflows (Docker Compose, Kubernetes, hyperparameter files). Its compactness also means smaller file sizes and faster version-control diffs.

XML is the better choice when the configuration must be exchanged with enterprise systems that require strict structure or XML Schema (XSD) validation, when interoperating with legacy systems that consume XML exclusively, or when working with existing OpenCV XML files such as pre-trained Haar cascade classifiers. XML’s verbosity is a drawback for human editing but a benefit for machine validation. In both cases data is saved by write and restored by getNode, so the format can be switched later by simply changing the file extension — no code changes required.
