1. Define computer vision and list its major application areas.

Computer vision (CV) is the branch of artificial intelligence that enables computers to acquire, process, analyse and understand digital images and videos so that they can extract meaningful information and act on it. In simple words, it teaches a machine to “see”: given an array of pixel values, the system must decide what is in the scene, where it is, and what it is doing. Image processing transforms an image into another image (denoise, sharpen); computer vision goes further and produces understanding (a label, a position, a measurement).

Typical computer-vision pipeline

Major application areas

  • Healthcare: tumour and fracture detection in X-ray, CT and MRI, cell counting, retinal screening.
  • Autonomous vehicles and robotics: lane, pedestrian, vehicle and traffic-sign detection, obstacle avoidance, visual navigation.
  • Security and surveillance: face recognition, intrusion detection, number-plate recognition, crowd monitoring.
  • Industry: defect inspection on production lines, barcode reading, measurement and sorting.
  • Agriculture and remote sensing: crop disease detection, yield estimation, land-use mapping from satellite images.
  • Retail and documents: product recognition, cashier-less stores, OCR and document scanning.
  • Augmented and virtual reality, entertainment: marker tracking, face filters, motion capture, photo enhancement.

Common tasks behind these applications are classification, object detection, segmentation, tracking, 3D reconstruction and image matching. Libraries such as OpenCV supply the building blocks for all of them, enabling rapid prototyping and deployment of vision systems across platforms.

Relationship with other AI fields

Computer vision overlaps with natural language processing in tasks such as image captioning and visual question answering, where a model must both see the image and generate language. It intersects with robotics through visual navigation and grasping, and with signal processing through the filtering and frequency-domain techniques that underpin many pre-processing steps. Modern multimodal models like CLIP and GPT-4V demonstrate that vision and language are converging into unified architectures.

Core tasks of computer vision

Most applications are built from a few basic tasks: image classification (what is in the image), object detection (what and where), segmentation (which pixels belong to which object), tracking (following an object through video), 3D reconstruction and pose estimation (depth and position), and recognition (identifying a particular face, character or gesture).

Computer vision and related fields

Image processing takes an image and produces another image (denoising, sharpening); computer vision takes an image and produces an understanding (labels, positions, measurements). Image processing is therefore usually the first stage inside a computer-vision system. Computer vision is also a part of artificial intelligence, since modern systems learn from data using machine learning and deep learning.

Why it is difficult

The same object looks different under changes in lighting, viewpoint, scale, occlusion and background clutter, and an image is only a 2D projection of a 3D world; a vision system must work correctly in spite of all these variations.

2. State the role of OpenCV in computer vision and identify its major features.

OpenCV (Open Source Computer Vision Library) is a free, open-source library (Apache 2.0 licence) of more than 2500 optimised algorithms for computer vision and machine learning. It is written in C++ with bindings for Python, Java and others, and runs on Windows, Linux, macOS, Android and iOS. Its role is to provide ready-made, fast building blocks so that a developer does not have to implement image reading, filtering, feature detection or camera calibration from scratch, and can move quickly from an idea to a working real-time application.

Major features

  • Image and video I/O: read, write and display images, files, webcams and streams (imread, VideoCapture).
  • Core data structures: the Mat class, which stores images as N-dimensional arrays, plus basic array maths.
  • Image processing: colour conversion, resizing, filtering, morphology, thresholding, edge detection, histograms.
  • Feature detection and matching: Harris, Shi-Tomasi, SIFT, ORB, FLANN matching, homography.
  • Object detection: Haar/LBP cascade classifiers, HOG, and the dnn module to run deep networks (YOLO, SSD) from ONNX or Caffe.
  • Video analysis: optical flow, background subtraction, object tracking.
  • 3D vision: camera calibration, stereo, pose estimation, undistortion.
  • Machine learning: SVM, k-NN, decision trees, k-means.
  • Performance: optimised C++, SIMD instructions, multithreading, OpenCL and CUDA acceleration.

The library is organised in modules, as the figure shows. Higher layers (detection, matching, calibration) are built on the processing layer, which in turn rests on the core data structures and the hardware. This layered design means a developer can mix high-level convenience functions with low-level pixel manipulation in the same application, choosing the right level of abstraction for each part of the pipeline.

Community and ecosystem

OpenCV has a vast community of contributors and a rich ecosystem of tutorials, sample code and pre-trained models. It integrates smoothly with NumPy, Matplotlib and deep-learning frameworks such as TensorFlow and PyTorch through its dnn module, which can load models in ONNX, Caffe and TensorFlow formats. This interoperability makes it a bridge between classical vision techniques and modern deep-learning approaches.

Why OpenCV is the standard choice

  • Free and open source (BSD licence), so it can be used in academic and commercial projects.
  • Multiple languages: C++ (core), Python, Java and others, so prototypes are quick and production code is fast.
  • Cross-platform: Windows, Linux, macOS, Android and iOS.
  • Optimised: highly tuned C++ with SIMD, multi-threading, OpenCL and CUDA support, which makes real-time use possible.
  • Large community and documentation, with many examples and tutorials.

Major modules

core (the Mat structure and basic operations), imgproc (filtering, thresholding, morphology, geometric transforms), imgcodecs and highgui (reading, writing and displaying images), videoio and video (camera access, tracking, optical flow), calib3d (calibration and 3D), features2d (keypoints and matching), objdetect (cascade classifiers), dnn (running trained deep networks) and ml (SVM, k-NN and other classic machine learning).

3. Explain the historical development of computer vision with a neat graph showing its major milestones.

Computer vision grew out of the wish to give machines human-like sight. Its history can be read as three eras: early geometry-based work, the feature-engineering era, and the current deep-learning era.

Major milestones

  • 1959: Hubel and Wiesel discover edge-sensitive neurons in the cat visual cortex, inspiring hierarchical feature detection.
  • 1963: Larry Roberts’ thesis recovers 3D block shapes from 2D images; 1966: the MIT Summer Vision Project optimistically tries to solve “vision” in one summer and shows how hard it is.
  • 1970s–80s: David Marr proposes a staged theory of vision (primal sketch → 2.5D sketch → 3D model); Fukushima’s Neocognitron (1980) anticipates CNNs; Canny (1986) and Harris (1988) give the standard edge and corner detectors.
  • 1989: LeCun trains a convolutional network to read handwritten zip-code digits.
  • 1999–2005: SIFT (Lowe) for scale-invariant features, Viola–Jones (2001) for real-time face detection, HOG (2005) for pedestrian detection. OpenCV is released by Intel in 2000.
  • 2009–2012: the ImageNet dataset (2009) and AlexNet (2012) show that deep CNNs trained on GPUs beat all hand-crafted methods.
  • 2014–2016: VGG, GoogLeNet, ResNet; R-CNN family and YOLO bring accurate real-time object detection.
  • 2020s: Vision Transformers (ViT), CLIP and large multimodal models connect vision with language.

Graph: effect of deep learning on image recognition

The graph shows the winning top-5 error of the ImageNet (ILSVRC) classification challenge. The sharp drop in 2012, when AlexNet replaced hand-crafted features, and the fall below the commonly quoted human error of about 5% by 2015 mark the turning point of the field.

Explanation of the milestones

  • 1960s–70s, beginnings: early work extracted simple 3D shapes and edges from images (block-world, edge detection), and the first digital image processing methods appeared. Computers were slow and data was scarce.
  • 1980s, mathematical foundations: edge detection (Canny), optical flow, stereo vision and the study of how the visual system builds a 3D description.
  • 1990s–2000s, feature and learning era: hand-designed features (corners, SIFT, HOG) combined with classifiers such as SVMs; the Viola-Jones face detector gave the first practical real-time detection; OpenCV was released.
  • 2012, deep learning: AlexNet reduced the ImageNet top-5 error sharply and started the switch from hand-crafted features to features learned by CNNs; error kept falling until it passed the human level (about 5%).
  • Today: deep detectors (YOLO), segmentation networks, vision transformers and multimodal models, running in real time on GPUs and mobile devices.

The graph shows how fast progress became once large datasets, GPUs and deep networks came together. This convergence, sometimes called the “deep learning revolution,” not only improved accuracy but also enabled real-time inference on edge devices, opening up consumer applications such as smartphone face unlock and drone navigation that were previously impractical.

4. Describe the procedure for installing and configuring OpenCV on Windows and explain the purpose of each major step.

OpenCV can be installed on Windows in two common ways: the quick Python route (a prebuilt package) or the C++ route (the official binaries linked into Visual Studio).

Route A: Python (recommended for learning)

  1. Install Python 3 from python.org and tick “Add Python to PATH”, so that python and pip work from any command prompt.
  2. Create a virtual environment (python -m venv cvenv, then cvenv\Scripts\activate) to keep library versions isolated per project.
  3. Install the package: pip install opencv-python (main modules). Use opencv-contrib-python instead if the extra modules (SIFT in older builds, tracking, xfeatures2d) are needed. NumPy is installed automatically because images are NumPy arrays.
  4. Verify: run the test below. If it prints a version number, the installation and the Python bindings work.
import cv2                      # load the OpenCV module (named cv2 for historical reasons)
print(cv2.__version__)          # prints e.g. 4.9.0 -> install is working
img = cv2.imread("test.jpg")    # quick functional test: read any image
print(img is not None)          # True means file I/O (imgcodecs) works

Route B: C++ with Visual Studio

  1. Download the Windows release from opencv.org and extract it, for example to C:\opencv. It contains headers (build\include), libraries (build\x64\vc16\lib) and DLLs (build\x64\vc16\bin).
  2. Set environment variables: create OPENCV_DIR = C:\opencv\build and add %OPENCV_DIR%\x64\vc16\bin to PATH, so that the program finds the DLLs at run time.
  3. Configure the Visual Studio project (platform x64): add the include folder under C/C++ → Additional Include Directories, the library folder under Linker → Additional Library Directories, and the library file (opencv_world490d.lib for Debug, opencv_world490.lib for Release) under Linker → Input. These three settings tell the compiler where the declarations are, tell the linker where the compiled code is, and name which library to link.
  4. Test with a small program that includes <opencv2/opencv.hpp>, reads and shows an image, and run it. A “DLL not found” error means the PATH step was missed; a linker error means the library path or name is wrong.

Alternatively OpenCV can be built from source with CMake, which allows custom options such as CUDA support, at the cost of a longer set-up.

Verifying the installation

Run import cv2; print(cv2.__version__) in Python; a version number means the installation works. For C++, build and run a small program that loads and shows an image. If the image window does not appear, check that the image path is correct and that waitKey is called.

Common problems and fixes

  • ModuleNotFoundError: No module named 'cv2': pip installed it into a different Python than the one being used; install again with that interpreter (python -m pip install opencv-python).
  • DLL not found (C++): the OpenCV bin folder is not in the PATH; add it and restart the IDE.
  • Linker errors (C++): the .lib files or their names (debug vs release, version number) are not set correctly in the project.
  • Architecture mismatch: the project platform (x64) must match the OpenCV build.

5. Explain the concept of a cross-platform development workflow in OpenCV. Why is it important in practical computer vision applications?

A cross-platform development workflow means writing an OpenCV application once, building and testing it on one operating system, and running it unchanged (or with only a rebuild) on others, such as Windows, Linux, macOS, Android or an embedded board. OpenCV supports this because it presents the same API on every platform, and platform-specific work (camera drivers, codecs, GUI back-ends) is hidden inside the library.

How the workflow is organised

  • Portable code: use only OpenCV and standard-language features; avoid Windows-only calls and hard-coded paths such as C:\data\img.jpg (use relative paths, os.path or pathlib).
  • Portable build system: CMake (C++) or pip with a requirements.txt (Python) generates the correct project for each OS, instead of a Visual Studio-only solution.
  • Version control and environments: Git for shared code, virtual environments or Docker containers to pin the same OpenCV version everywhere.
  • Automated testing: a continuous-integration server builds and tests on Windows and Linux, so a platform-specific bug is caught early.
  • Hardware abstraction: VideoCapture uses DirectShow on Windows, V4L2 on Linux and AVFoundation on macOS, but the program just calls cap.read().

Why it is important in practice

Computer-vision products are rarely deployed where they are written. A model is prototyped on a laptop, trained on a Linux GPU server, and finally run on a Raspberry Pi, a Jetson, a phone or a cloud service. A cross-platform workflow avoids rewriting code for each target, keeps results consistent, lets teams with different machines collaborate, reduces cost and speeds up delivery, and makes the system easier to maintain and upgrade.

Challenges and how they are handled

ChallengeSolution
Different compilers and build systemsCMake generates the right project files for each platform
Different file path styles and image foldersUse relative paths or portable path functions (os.path, std::filesystem)
Different camera and codec supportTest VideoCapture on each platform; pick a supported backend and codec
Library versions differ between machinesFix versions in requirements.txt or a virtual environment; use Git for the source
Different hardware (CPU, GPU, mobile)Keep the algorithm separate from the platform code; enable CUDA/OpenCL only where available

Importance in practice: a model prototyped on a laptop is often deployed on a Linux server, a Raspberry Pi or an Android phone. A portable workflow means the same code runs everywhere with little change, saves porting time, and lets a team on different operating systems work on one project. Without cross-platform design, teams waste weeks porting code to each target, debugging platform-specific issues that should have been caught early. Industry projects such as autonomous driving and smart surveillance routinely deploy the same codebase across cloud, edge and mobile environments.

6. Demonstrate how an image can be loaded, displayed, modified, and saved using OpenCV.

Every OpenCV program begins with the same four operations: load (bring a file from disk into memory as a matrix), display (render the matrix in a window for visual inspection), modify (apply any transformation to the pixel data), and save (write the resulting matrix back to a file). These map directly to the functions imread, imshow, an editing step, and imwrite. Understanding this pipeline is fundamental because every subsequent OpenCV task, from simple filtering to complex detection, follows the same structure of reading pixel data, processing it, and outputting the result.

Steps in words

  1. Load: cv2.imread(path, flag) reads the file into a NumPy array in BGR order. The flag selects the mode: IMREAD_COLOR (default), IMREAD_GRAYSCALE or IMREAD_UNCHANGED (keeps the alpha channel). If the path is wrong, it does not raise an error; it returns None, so always check.
  2. Display: cv2.imshow(window_name, img) opens a window; cv2.waitKey(0) waits for a key (without it the window closes at once); cv2.destroyAllWindows() closes the windows.
  3. Modify: because the image is an array, any array operation changes it: convert colour (cvtColor), draw shapes and text (rectangle, putText), change pixels (img[y, x] = (0, 0, 255)), blur or threshold.
  4. Save: cv2.imwrite(filename, img) writes the image; the format follows the extension (.jpg, .png); it returns True on success.

Why BGR and not RGB

OpenCV was originally developed in the late 1990s when BGR was the dominant ordering in camera hardware and Windows bitmap formats. This convention persisted for backward compatibility. When integrating OpenCV with libraries that expect RGB, such as Matplotlib or PIL, an explicit cv2.cvtColor(img, cv2.COLOR_BGR2RGB) conversion is required, otherwise reds appear blue and vice versa.

Internal representation

Internally, imread decodes the file format (JPEG, PNG, BMP, TIFF) and produces a dense NumPy array of shape (height, width, channels) with dtype=uint8 by default. Each pixel occupies one byte per channel, giving values 0–255. Grayscale images have shape (height, width) with no channel dimension, which matters when performing channel-wise operations.

Common mistakes

Not checking for None after imread is the most frequent beginner error, because the function silently returns None on an invalid path instead of raising an exception. Forgetting waitKey after imshow causes the window to freeze or close instantly. Expecting RGB order leads to swapped colours when plotting. Modifying the original array instead of calling copy() first means the original data is lost permanently.

import cv2                                  # OpenCV library

img = cv2.imread("lena.jpg")                # LOAD: returns a NumPy array in BGR order, or None if the path is wrong
if img is None:                             # always check, imread does not raise an error
    raise FileNotFoundError("image not found")

print(img.shape, img.dtype)                 # e.g. (512, 512, 3) uint8 -> (rows=height, cols=width, channels)

cv2.imshow("Original", img)                 # DISPLAY: first argument is the window title
cv2.waitKey(0)                              # wait for a key press; without it the window closes/hangs at once

gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)  # MODIFY 1: colour -> grayscale (BGR2GRAY: "from BGR to GRAY")
img[100:150, 100:200] = (0, 0, 255)         # MODIFY 2: paint a block red; slicing is [rows, cols]; colour is (B, G, R)
cv2.rectangle(img, (50, 50), (250, 250), (0, 255, 0), 2)  # MODIFY 3: green box, corners are (x, y), thickness 2

cv2.imshow("Modified", img)                 # show the changed image
cv2.waitKey(0)
cv2.destroyAllWindows()                     # close all windows to free resources

cv2.imwrite("output.png", img)              # SAVE: format is chosen from the extension (.png lossless, .jpg lossy)
cv2.imwrite("gray.jpg", gray, [cv2.IMWRITE_JPEG_QUALITY, 90])  # optional quality parameter

Points to remember. (1) OpenCV stores colour as BGR, not RGB. (2) imread flags: IMREAD_COLOR (default), IMREAD_GRAYSCALE and IMREAD_UNCHANGED (keeps the alpha channel and bit depth). (3) imshow needs waitKey to refresh the window. (4) Pixels are indexed [row, column] = [y, x], but drawing functions take points as (x, y). (5) Saving a JPEG repeatedly loses quality; use PNG for lossless storage.

Practical considerations

When saving, the output format is determined entirely by the file extension passed to imwrite. JPEG is lossy and produces smaller files, making it suitable for photographs; PNG is lossless and supports transparency, making it better for processed results where precision matters. Repeatedly saving and reloading a JPEG introduces cumulative quality loss known as generation loss, so intermediate results should be kept as PNG or in memory.

Expected output: a window showing the loaded image; after modification, a second window with the changed image; a new file saved on disk.

7. Apply basic OpenCV operations to resize, crop, and rotate a given image.

Resizing, cropping and rotating are the three most common geometric transformations in computer vision. Resizing changes the dimensions of the entire image, cropping extracts a rectangular sub-region, and rotation moves pixels around a chosen centre point. All three operate on the NumPy array returned by imread and produce a new array as output. These operations are essential in nearly every CV pipeline: neural networks require a fixed input size, object detectors work on cropped regions of interest, and document scanners must correct tilt before OCR can proceed.

Steps in words

  1. Resize with cv2.resize(img, (width, height)) or with scale factors fx, fy. Note the order: the size tuple is (width, height), but img.shape gives (height, width). Interpolation: INTER_AREA for shrinking, INTER_LINEAR (default) or INTER_CUBIC for enlarging.
  2. Crop by array slicing: img[y1:y2, x1:x2]. Rows (y) come first. The result is a view of the same memory, so use .copy() if the original must stay unchanged.
  3. Rotate: compute the matrix with cv2.getRotationMatrix2D(center, angle, scale) (positive angle = counter-clockwise) and apply it with cv2.warpAffine(img, M, (w, h)). For exact multiples of 90° use the simpler cv2.rotate(img, cv2.ROTATE_90_CLOCKWISE).

Common mistakes: swapping x and y in the slice; giving (height, width) to resize; rotating about the top-left corner instead of the centre; corners cut off after rotation because the output size was not enlarged.

import cv2

img = cv2.imread("lena.jpg")
h, w = img.shape[:2]                                   # height (rows) and width (cols); [:2] drops channels

# ---- RESIZE ----
small = cv2.resize(img, (w // 2, h // 2),              # dsize is (width, height): order differs from shape!
                   interpolation=cv2.INTER_AREA)       # INTER_AREA best for shrinking
big = cv2.resize(img, None, fx=2, fy=2,                # or give scale factors instead of a size
                 interpolation=cv2.INTER_CUBIC)        # INTER_CUBIC / INTER_LINEAR best for enlarging

# ---- CROP ----
roi = img[50:200, 100:300]                             # NumPy slicing [y1:y2, x1:x2]; a view, not a copy
roi = img[50:200, 100:300].copy()                      # .copy() if you will edit it independently

# ---- ROTATE ----
r90 = cv2.rotate(img, cv2.ROTATE_90_CLOCKWISE)         # fast exact rotation by 90, 180 or 270 degrees
M = cv2.getRotationMatrix2D((w / 2, h / 2), 45, 1.0)   # (centre, angle in degrees (+ = anticlockwise), scale)
rot = cv2.warpAffine(img, M, (w, h))                   # apply the 2x3 matrix; output size is (w, h)

cv2.imwrite("rot45.jpg", rot)

For rotation by an arbitrary angle, OpenCV builds a \(2\times3\) affine matrix:

\[ M=\begin{bmatrix}\alpha&\beta&t_x\\-\beta&\alpha&t_y\end{bmatrix},\qquad \alpha=s\cos\theta,\quad \beta=s\sin\theta \]

Here \(\theta\) is the rotation angle, \(s\) is the scale factor (1 keeps the size), and \(t_x,t_y\) are shifts chosen so that the chosen centre stays in place instead of rotating about the top-left corner. warpAffine multiplies every pixel position by \(M\) to find its new position. In practice this means: pick the centre, angle and scale, and OpenCV returns the matrix. Note that a 45° rotation with the same output size cuts off the corners; enlarge the output canvas if the whole image must be kept.

Interpolation is needed because new pixel positions rarely fall exactly on the old grid: nearest-neighbour is fastest but blocky, bilinear is a good default, bicubic is smoother but slower, and INTER_AREA avoids aliasing when shrinking.

Applications in practice

Resizing is used to convert images to the fixed input size expected by neural networks, such as 224×224 for VGG or 416×416 for YOLO. Cropping extracts regions of interest like detected faces for recognition or number plates for OCR. Rotation corrects the tilt in scanned documents, aligns satellite imagery, and serves as a popular data-augmentation technique during training, where random rotations make the model invariant to orientation changes.

Performance notes

Cropping via slicing is the fastest operation because it does not copy data; the returned array is a view into the same memory. Resizing and rotation involve pixel interpolation, which is more expensive. For video streams at 30 fps, choosing INTER_LINEAR over INTER_CUBIC can save several milliseconds per frame while producing acceptable visual quality for most downstream tasks.

8. Analyze how an image is represented as a matrix and examine the relationship between image dimensions, pixels, and matrix elements.

A digital image is a two-dimensional grid of tiny elements called pixels. In OpenCV (and NumPy) this grid is stored as a matrix, so every image operation is really an operation on numbers. Each matrix element holds the intensity of one pixel: a grayscale image is an \(M\times N\) matrix (one value per pixel), while a colour image is an \(M\times N\times 3\) array with three values (blue, green, red) per pixel.

Relationship between dimensions, pixels and matrix elements

  • Height = number of rows and width = number of columns. In code, img.shape returns (rows, cols, channels), that is (height, width, channels).
  • Pixel = one matrix element addressed by img[row, col], which is img[y, x]. The origin (0,0) is the top-left corner; y grows downwards and x grows to the right.
  • Total pixels \(=\) rows \(\times\) columns. The number of stored values is that times the number of channels.
  • Value range: for the usual 8-bit type (uint8), intensities are 0 (black) to 255 (white); each value takes one byte.
\[ \text{size (bytes)} = H \times W \times C \times b \]

Here \(H\) is the height (rows), \(W\) is the width (columns), \(C\) is the number of channels (1 for gray, 3 for colour) and \(b\) is the bytes per value (1 for uint8). The formula tells how much memory an image needs: a 1920×1080 colour frame needs \(1080\times1920\times3\times1=6{,}220{,}800\) bytes, about 6 MB, which is why speed and memory matter in video processing.

Why the matrix view is useful. Because an image is a matrix, filtering becomes a neighbourhood multiplication, brightness change becomes adding a constant, cropping becomes slicing, and a whole image can be processed with fast vectorised array operations. In memory the rows are stored one after another (row-major) and the channels of a pixel sit next to each other (B0 G0 R0 B1 G1 R1 …).

Types of images by matrix content

TypeMatrixValues
Binary\(M\times N\)0 or 1 (0 or 255 when displayed)
Grayscale\(M\times N\)0–255 (8-bit): one intensity per pixel
Colour (BGR)\(M\times N\times3\)Three 0–255 values per pixel (blue, green, red)

OpenCV stores colour in BGR order rather than the more common RGB, a legacy of early camera hardware conventions. The bit depth sets the number of possible values: 8 bits give 256 levels, and a 16-bit or float image holds finer values. The useful attributes of the array are img.shape (rows, columns, channels), img.size (total number of values), img.dtype (data type) and img[y, x] (one pixel). Example: for a 480×640 colour image, shape = (480, 640, 3), there are \(480\times640=307{,}200\) pixels and \(307{,}200\times3=921{,}600\) stored values.

9. A program successfully loads an image, but the displayed image appears completely black. Analyze the possible causes and suggest suitable solutions.

If imread succeeded (the result is not None) but imshow shows black, the pixel values or the way they are displayed are wrong. A black image means the values are all (or nearly all) 0, or are being mapped to 0. The first step is always to print the array statistics and then follow the checklist below.

Possible causes and solutions

CauseWhy it looks blackSolution
The image really is dark or emptyThe file contains very low values (under-exposed or a blank/transparent PNG)Open the file in another viewer; use brightness/contrast correction or histogram equalization
Wrong data type or rangeValues were divided by 255 (0–1) and then cast to uint8, so they all become 0; a 16-bit image shown as 8-bit appears very darkMultiply back ((img*255).astype('uint8')), or use cv2.normalize(img, None, 0, 255, cv2.NORM_MINMAX) / cv2.convertScaleAbs
Alpha / unchanged flagLoaded with IMREAD_UNCHANGED and the transparent areas are shown as black, or only the alpha channel was displayedLoad with IMREAD_COLOR or split the channels and display the colour part
Previous operation zeroed the dataA slice assignment (img[:] = 0), a mask of all zeros in bitwise_and, a wrong ROI, or subtraction that saturates at 0Print values after each step; check masks and ROI coordinates; use cv2.add/subtract deliberately
Display problemNo waitKey(), so the window is created but never painted; wrong variable shownCall cv2.waitKey(0) after imshow and display the correct array
Created image instead of loadednp.zeros(...) was used as the image and the real data was never copied inVerify the variable that is shown and that the data is written into it
img = cv2.imread("photo.jpg", cv2.IMREAD_UNCHANGED)   # load without altering depth or channels
print(img.shape, img.dtype, img.min(), img.max())    # diagnosis: if min = max = 0 the data itself is black
if img.dtype != "uint8":                             # float or 16-bit -> convert for display
    img = cv2.normalize(img, None, 0, 255, cv2.NORM_MINMAX).astype("uint8")
cv2.imshow("check", img)
cv2.waitKey(0)                                       # needed, otherwise nothing is drawn

Method: inspect (shape, dtype, min, max) → check range and type → check display call → walk back through the processing steps, and fix the first place where the values become zero.

Systematic debugging approach

Quick diagnosis order: (1) check img is None and the path; (2) print img.shape, img.dtype, img.min(), img.max(); (3) if the values are fine, the fault is in display (waitKey, wrong variable shown); (4) if the values are zero, trace backwards through the processing steps to find the one that produced them (a division, a mask, a type cast).

Why this matters in real systems

In production pipelines, a black or corrupted frame can silently propagate through the entire processing chain, producing meaningless detections or measurements. Building the habit of checking shape, dtype and value range at every stage of the pipeline is essential for robust CV systems. Logging these diagnostics automatically helps catch intermittent failures in deployed applications, such as camera dropouts in surveillance systems or corrupted frames in video streams.

10. Evaluate the importance of OpenCV in developing practical and real-time computer vision applications. Justify your answer with suitable examples.

OpenCV is the standard working library of practical computer vision. It gives developers a fast, free and tested toolbox, so that real systems can be built in days rather than months. Its importance can be evaluated under the following points.

  • Real-time performance. The core is optimised C++ with SIMD instructions, multithreading, and optional OpenCL/CUDA acceleration. Real-time video needs each frame processed within the frame time:
\[ t_{\text{frame}} = \frac{1000}{\text{FPS}}\ \text{ms} \]

Here FPS is the frames per second and \(t_{\text{frame}}\) is the time available to process one frame. At 30 FPS the whole pipeline must finish in about 33 ms.   • Breadth. One library covers I/O, filtering, features, detection, tracking, calibration, 3D and machine learning, and its dnn module runs deep models (YOLO, SSD, ONNX) without a separate framework.
  • Accessibility. Open source, free for commercial use, cross-platform, with C++, Python and Java interfaces, large documentation and community.
  • Integration. Works with NumPy, Matplotlib, TensorFlow/PyTorch pipelines and hardware such as Raspberry Pi and Jetson.

Evaluation and limits. OpenCV is excellent for pre-processing, classical algorithms and deploying models in real time, but it is not a deep-learning training framework, and its low-level API needs careful use. For the hardest recognition tasks it is combined with deep-learning libraries, with OpenCV doing the surrounding image handling and display. Overall it is the most practical foundation for real-time computer-vision systems because it combines speed, completeness and availability.

Why it supports real-time use

  • Speed: C++ core with vectorised and parallel code, plus GPU back-ends, so each frame can be processed within the 33 ms budget of 30 fps video.
  • Complete toolbox: capture, pre-processing, feature detection, tracking, calibration and deep-network inference are in one library, so a full application needs no extra glue code.
  • Hardware reach: runs on desktops, embedded boards (Raspberry Pi, Jetson) and phones, which is where real-time systems are deployed.
  • Rapid development: Python bindings let ideas be tested in minutes, and the same logic can be moved to C++ for production.

Justification: examples such as lane detection in driver-assistance systems, face detection in cameras, barcode and number-plate readers, and industrial defect inspection all combine fast frame capture, classic filtering and detection, and sometimes a neural network, and all of them are routinely built with OpenCV.
