41. Define SVM-based image classification and identify the major components involved in the classification process.

SVM-based image classification assigns an image to one of several predefined categories (e.g. "cat", "dog", "car") by first converting the raw pixel data into a compact, discriminative feature vector and then feeding it to a Support Vector Machine — a supervised classifier that finds the hyperplane separating two classes with the largest possible margin, meaning the widest empty gap between the nearest samples of each class. The key insight behind SVMs is that among all hyperplanes that correctly separate the training data, the one with the maximum margin generalises best to unseen images because it is least sensitive to small shifts in the input. For problems with more than two classes, the system trains multiple binary SVMs (one-vs-rest, where each SVM separates one class from all others, or one-vs-one, where a separate SVM is trained for every pair of classes) and combines their votes to produce the final label.

Major components

  1. Labelled dataset: images with known classes, split into training and test sets.
  2. Pre-processing: resize to a fixed size, convert to gray, normalise, remove noise.
  3. Feature extraction: raw pixels are too many and too sensitive, so each image is turned into a compact feature vector, e.g. HOG (histogram of oriented gradients), colour histograms or SIFT/ORB descriptors.
  4. SVM training: the vectors and labels are used to find the separating hyperplane; the training samples closest to it are the support vectors and alone define the boundary.
  5. Kernel: if the classes are not linearly separable, a kernel maps the vectors to a higher-dimensional space where they can be separated (linear, polynomial, RBF).
  6. Prediction and evaluation: a new image is converted to a feature vector and classified; accuracy is measured on the test set.
\[ f(\mathbf{x})=\operatorname{sign}(\mathbf{w}\cdot\mathbf{x}+b),\qquad \text{margin}=\frac{2}{\lVert\mathbf{w}\rVert},\qquad K(\mathbf{x},\mathbf{z})=e^{-\gamma\lVert\mathbf{x}-\mathbf{z}\rVert^{2}} \]

\(\mathbf{x}\) is the feature vector of an image, \(\mathbf{w}\) is the normal (direction) of the hyperplane and \(b\) its offset; the sign of \(\mathbf{w}\cdot\mathbf{x}+b\) tells on which side the image lies, i.e. its class. Training chooses the \(\mathbf{w}\) with the smallest \(\lVert\mathbf{w}\rVert\), which means the widest margin. The RBF kernel \(K\) measures the similarity between two vectors in a higher-dimensional space where the data may become linearly separable even when it is not in the original feature space — the parameter \(\gamma\) controls how local the kernel is (high \(\gamma\) means only very close points influence each other, risking overfitting; low \(\gamma\) means broader influence, risking underfitting). The regularisation parameter \(C\) controls the trade-off between a wide margin and training accuracy: a large \(C\) penalises misclassifications heavily and fits the training data tightly, while a small \(C\) tolerates some errors in exchange for a smoother, more generalisable decision boundary. In practice, \(C\) and \(\gamma\) are tuned together using cross-validation on the training set.

import cv2, numpy as np
hog = cv2.HOGDescriptor((64, 128), (16, 16), (8, 8), (8, 8), 9)   # HOG: window, block, block stride, cell, orientation bins
def feat(path):
    img = cv2.resize(cv2.imread(path, 0), (64, 128))      # fixed size gray image
    return hog.compute(img).flatten()                     # feature vector (3780 numbers)

X = np.float32([feat(p) for p in train_paths])            # one row per image; SVM needs float32
y = np.int32(train_labels).reshape(-1, 1)                 # class labels as int32, one per row

svm = cv2.ml.SVM_create()
svm.setType(cv2.ml.SVM_C_SVC)                             # classification SVM
svm.setKernel(cv2.ml.SVM_RBF)                             # RBF kernel for non-linear boundaries
svm.setC(2.5); svm.setGamma(0.5)                          # C = penalty, gamma = kernel width
svm.train(X, cv2.ml.ROW_SAMPLE, y)                        # ROW_SAMPLE: each row is one sample
_, pred = svm.predict(np.float32([feat("test.jpg")]))     # returns (retval, predicted labels)
print(int(pred[0, 0]))

42. Explain camera calibration and distinguish between intrinsic and extrinsic camera parameters.

Camera calibration is the process of estimating the mathematical parameters that describe exactly how a real camera projects three-dimensional world points onto its two-dimensional image sensor — in other words, building a precise model of the camera so that pixel coordinates can be converted into physical measurements and vice versa. Every real camera introduces both geometric projection effects (perspective foreshortening) and optical imperfections (lens distortion), and without knowing the camera's parameters these effects make it impossible to perform accurate 3D reconstruction, stereo depth estimation, augmented-reality overlay or even simple distance measurement from an image. Calibration is typically performed by photographing a known calibration target — most commonly a flat chessboard pattern with precisely spaced squares — from 10–20 different positions and orientations, then running an optimisation that finds the parameter values that best explain the detected corner positions across all views simultaneously.

\[ s\begin{bmatrix}u\\v\\1\end{bmatrix}=\underbrace{\begin{bmatrix}f_x&0&c_x\\0&f_y&c_y\\0&0&1\end{bmatrix}}_{K}\,\underbrace{\begin{bmatrix}R\mid \mathbf{t}\end{bmatrix}}_{\text{extrinsic}}\begin{bmatrix}X\\Y\\Z\\1\end{bmatrix} \]

\((X,Y,Z)\) is a point in the world, \((u,v)\) its pixel position and \(s\) a scale factor. \([R\mid\mathbf{t}]\) moves the point from world coordinates into the camera's coordinates; \(K\) then projects it onto the image. In use: once \(K\), the distortion coefficients and the pose are known, a pixel can be turned into a ray in space, or a 3D point can be projected to find its pixel.

Intrinsic and extrinsic parameters

IntrinsicExtrinsic
DescribesThe camera's internal geometryThe camera's position and orientation in the world
ParametersFocal lengths \(f_x,f_y\) (in pixels), principal point \((c_x,c_y)\) (image centre), skew, lens distortion coefficients \(k_1,k_2,p_1,p_2,k_3\)Rotation matrix \(R\) (3 angles) and translation vector \(\mathbf{t}\) (3 values)
Changes whenZoom, focus or lens changes; fixed for a given camera settingThe camera or object moves; different for every picture
Found forOnce per cameraEvery image

Procedure

  1. Print a chessboard on a rigid flat surface and photograph it in 10–20 different poses, varying both angle and distance so that the corners cover the whole image area — edge coverage is important because distortion is strongest there.
  2. Detect the inner corners (findChessboardCorners) and refine them to subpixel accuracy using cornerSubPix, which fits a local intensity model to push each corner location from whole-pixel to roughly 0.01-pixel precision.
  3. Pair the detected 2D corners with their known 3D positions on the board (the board plane is defined as Z = 0, with squares typically set to unit spacing).
  4. Run calibrateCamera, which solves a non-linear least-squares problem to find the intrinsic matrix \(K\), the five distortion coefficients, and a separate rotation-translation pose for every image; the returned reprojection error (ideally below 0.5 pixel) measures how well the model fits.

After calibration is complete the intrinsic matrix and distortion coefficients are saved once and reused for every future frame from that camera, while new extrinsic parameters are computed per frame only when the camera or scene moves. Industrial pipelines often recalibrate periodically because thermal expansion and mechanical vibration shift the lens over time, making an outdated calibration file a hidden source of systematic error in measurements.

import cv2, numpy as np, glob
pattern = (9, 6)                                          # inner corners per row and column of the chessboard
objp = np.zeros((pattern[0] * pattern[1], 3), np.float32)
objp[:, :2] = np.mgrid[0:pattern[0], 0:pattern[1]].T.reshape(-1, 2)   # 3D corner positions (0,0,0), (1,0,0), ... Z = 0
objpoints, imgpoints = [], []                             # collected 3D points and matching 2D points
for f in glob.glob("calib/*.jpg"):
    gray = cv2.imread(f, 0)
    ok, corners = cv2.findChessboardCorners(gray, pattern)   # ok is False if the board is not found
    if ok:
        criteria = (cv2.TERM_CRITERIA_EPS + cv2.TERM_CRITERIA_MAX_ITER, 30, 0.001)
        corners = cv2.cornerSubPix(gray, corners, (11, 11), (-1, -1), criteria)   # subpixel refinement
        objpoints.append(objp); imgpoints.append(corners)
err, K, dist, rvecs, tvecs = cv2.calibrateCamera(objpoints, imgpoints, gray.shape[::-1], None, None)
print(K)                                                  # intrinsic matrix (fx, fy, cx, cy)
print(dist)                                               # k1, k2, p1, p2, k3; rvecs/tvecs = extrinsics per image

43. Explain image undistortion and describe how camera calibration parameters are used to correct lens distortion.

An ideal pinhole camera projects the world perfectly — straight lines remain straight and angles are preserved — but real lenses are curved pieces of glass that refract light unevenly, causing straight edges in the scene to appear bowed or warped in the photograph, especially toward the image borders. Image undistortion is the process of computationally reversing this optical distortion using the distortion coefficients estimated during camera calibration (the five numbers \(k_1, k_2, p_1, p_2, k_3\)), producing a corrected image that behaves as if it came from a perfect pinhole camera. This correction is a prerequisite for virtually all geometric computer vision tasks — stereo depth estimation, panorama stitching, visual SLAM, photogrammetric measurement and augmented-reality registration all assume the pinhole model, and operating on distorted images introduces systematic errors that grow toward the image edges.

Types of lens distortion

  • Radial distortion: magnification changes with the distance from the image centre, giving barrel (edges bulge outward, wide-angle lenses) or pincushion (edges pinch inward, telephoto) shapes.
  • Tangential distortion: the lens is not perfectly parallel to the sensor, so the image looks slightly tilted or skewed.
\[ x_d=x\,(1+k_1r^{2}+k_2r^{4}+k_3r^{6})+\big[2p_1xy+p_2(r^{2}+2x^{2})\big],\qquad r^{2}=x^{2}+y^{2} \]

\((x,y)\) is an ideal, undistorted point in normalised camera coordinates (relative to the principal point and divided by the focal length), \(r\) is its distance from the centre and \((x_d,y_d)\) is where the lens actually puts it (\(y_d\) has the same form). \(k_1,k_2,k_3\) are radial coefficients and \(p_1,p_2\) tangential ones; these five numbers are the dist vector from calibration. Undistortion inverts this mapping: for each pixel of the corrected image, the formula tells which pixel of the distorted image to read.

Steps

  1. Obtain \(K\) and the distortion coefficients from calibration (Q42).
  2. Optionally compute a new camera matrix with getOptimalNewCameraMatrix; the parameter \(\alpha\) decides whether black borders are kept (\(\alpha=1\), all pixels) or cropped (\(\alpha=0\)).
  3. Correct the image: either undistort directly, or build the maps once with initUndistortRectifyMap and apply remap to every frame (faster for video).
  4. Crop the valid region of interest if needed.
import cv2, numpy as np
img = cv2.imread("distorted.jpg")
h, w = img.shape[:2]
# K and dist come from cv2.calibrateCamera (Q42)
newK, roi = cv2.getOptimalNewCameraMatrix(K, dist, (w, h), 1, (w, h))   # alpha = 1 keeps all pixels (black edges possible)
und = cv2.undistort(img, K, dist, None, newK)             # one-shot correction
x, y, rw, rh = roi                                        # valid area without black borders
und = und[y:y + rh, x:x + rw]                             # crop to it

mapx, mapy = cv2.initUndistortRectifyMap(K, dist, None, newK, (w, h), cv2.CV_32FC1)   # build lookup maps once
und2 = cv2.remap(img, mapx, mapy, cv2.INTER_LINEAR)       # reuse for each video frame: same result, faster

Why correction matters

Uncorrected distortion makes straight objects look curved and distances measured near the image border systematically wrong — a measurement that is accurate at the image centre can be off by several percent near the corners. This breaks stereo matching (which assumes epipolar lines are straight), panorama stitching (which assumes a projective model) and any 3D reconstruction that relies on accurate point correspondences. Wide-angle, action cameras (GoPro) and phone cameras show the strongest barrel distortion due to their short focal lengths, while telephoto lenses exhibit milder pincushion effects. The calibration procedure only needs to be performed once per physical camera and lens setting — the intrinsic matrix \(K\) and the five distortion coefficients remain constant as long as the zoom and focus are unchanged, so the same parameters correct every image or video frame taken with that configuration, making the one-time calibration cost negligible in production systems.

44. Explain the fundamental principles and major stages of 3D reconstruction from images.

3D reconstruction recovers the three-dimensional structure of a scene from two or more 2D images taken from different viewpoints — it is the core enabling technology behind autonomous-vehicle perception, augmented-reality scene understanding and medical volumetric imaging. The basic principle is triangulation: a point that is seen in two images lies on two viewing rays originating from their respective camera centres, and the 3D point is the location in space where those rays intersect. Nearby points shift more between the views than distant ones, and this shift (disparity) directly encodes depth, making stereo vision analogous to how human binocular vision perceives distance by comparing the slightly different images each eye receives.

\[ Z=\frac{f\,B}{d},\qquad d=x_L-x_R \]

\(Z\) is the depth of the point from the cameras, \(f\) the focal length in pixels, \(B\) the baseline (distance between the two camera centres) and \(d\) the disparity (difference of the point's x-position in the left and right images). Depth is inversely proportional to disparity: for \(f=700\) px, \(B=0.1\) m and \(d=35\) px, \(Z=700\times0.1/35=2\) m. A larger baseline or focal length gives better depth accuracy at long range, but increasing the baseline also makes it harder to find correspondences for very close objects because their disparity exceeds the search window. In practice, indoor systems use baselines of 5–12 cm (similar to human eye spacing) while autonomous vehicles may use 30–50 cm for longer range.

Major stages

  1. Camera calibration to get the intrinsic parameters and remove lens distortion so that straight lines in the world remain straight in the image — without this step, triangulation geometry is built on a warped foundation and depth errors grow rapidly.
  2. Rectification: warp both images so that corresponding points lie on the same row, which turns the search for matches into an efficient 1D search along that row (the epipolar constraint) instead of a costly 2D search across the entire image.
  3. Correspondence: find matching points in the two images, either sparse (feature matching with SIFT or ORB keypoints) or dense (block matching / semi-global matching for every pixel), producing a disparity map where brightness encodes depth.
  4. Triangulation: compute depth from disparity using the formula above (or from the camera projection matrices directly) to recover 3D coordinates for each matched point.
  5. Point cloud and refinement: collect the 3D points into a point cloud or mesh, remove statistical outliers and optionally refine all camera poses and points together using bundle adjustment, a large-scale non-linear optimisation that minimises the total reprojection error across all views. For a single moving camera (structure from motion) the relative pose between consecutive frames is first estimated from the essential matrix computed from matched features, and the point cloud grows incrementally as new frames are added.
import cv2, numpy as np
L = cv2.imread("left.png", 0); R = cv2.imread("right.png", 0)       # rectified grayscale pair
stereo = cv2.StereoSGBM_create(minDisparity=0, numDisparities=64, blockSize=5)   # numDisparities must be a multiple of 16
disp = stereo.compute(L, R).astype(np.float32) / 16.0     # SGBM returns fixed point; divide by 16 for pixels
# Q is the 4x4 reprojection matrix produced by cv2.stereoRectify during calibration
points = cv2.reprojectImageTo3D(disp, Q)                  # (h, w, 3): X, Y, Z for every pixel
valid = disp > disp.min()                                 # ignore pixels with no match
cloud = points[valid]                                     # N x 3 array of 3D points

45. Explain GPU-accelerated processing in computer vision and discuss its advantages and limitations.

GPU-accelerated processing moves heavy image computations from the CPU to the graphics processor, and it has become essential in modern computer vision because real-time applications such as autonomous driving and video surveillance demand the processing of millions of pixels per frame at 30 fps or higher — a throughput that serial CPU execution simply cannot sustain. Most image operations are data-parallel: the same small calculation (a filter at one pixel, a colour conversion) is repeated independently for millions of pixels. A CPU has a few powerful cores working through pixels largely one after another, while a GPU has hundreds or thousands of simple cores that process many pixels at the same instant, like one chef cooking dishes one by one versus a large kitchen team each plating a dish simultaneously. This architectural difference means that for embarrassingly parallel tasks like convolution, thresholding and histogram computation, the GPU's aggregate throughput can exceed the CPU's by one to two orders of magnitude.

In OpenCV this is available through the CUDA module (cv2.cuda, NVIDIA GPUs, data held in GpuMat) and through the Transparent API (UMat with OpenCL, working on many GPU brands with the usual function names). The processing sequence is shown below.

AdvantagesLimitations
Large speed-up (often 5–50 times) for filtering, resizing, optical flow, stereo matching and deep-network inferenceCopying data between CPU and GPU memory takes time and can cancel the gain for small images or simple operations
Real-time processing of HD/4K video and multiple streamsNeeds suitable hardware (CUDA needs an NVIDIA GPU) and an OpenCV build with CUDA; the standard pip package does not include it
Frees the CPU for other tasks; better performance per watt for parallel workGPU memory is limited; only a subset of OpenCV functions is implemented on the GPU
Makes heavy methods (deep learning, dense matching) practicalBranch-heavy, sequential or irregular algorithms do not run well; code is harder to write and debug

Rule of thumb: keep data on the GPU through the whole chain of operations and copy only the final result back, otherwise the transfer cost hides the speed-up. In a typical pipeline — read frame, upload, colour-convert, blur, edge-detect, download — the upload and download are each 1–3 ms over PCIe, while the four GPU kernels together may take only 0.5 ms on a modern card; if you uploaded and downloaded between every step the transfers would dominate the total time. When choosing between the CUDA module and the Transparent API, the trade-off is portability versus control: UMat code runs unchanged on Intel, AMD and NVIDIA hardware through OpenCL but cannot access CUDA-only features like cuDNN or CUDA streams, whereas the CUDA module exposes the full power of NVIDIA hardware at the cost of vendor lock-in.

import cv2
img = cv2.imread("big.jpg")

# --- CUDA module (needs OpenCV built with CUDA) ---
g = cv2.cuda_GpuMat()                                     # container in GPU memory
g.upload(img)                                             # copy CPU -> GPU
g = cv2.cuda.cvtColor(g, cv2.COLOR_BGR2GRAY)              # runs on the GPU
blur = cv2.cuda.createGaussianFilter(cv2.CV_8UC1, cv2.CV_8UC1, (7, 7), 0)   # create the filter object once
g = blur.apply(g)                                         # filter on the GPU, no copy back yet
out = g.download()                                        # copy GPU -> CPU only at the end

# --- Transparent API (OpenCL, usual function names) ---
u = cv2.UMat(img)                                         # wrap the image; OpenCV picks GPU if available
u = cv2.GaussianBlur(cv2.cvtColor(u, cv2.COLOR_BGR2GRAY), (7, 7), 0)
out2 = u.get()                                            # bring the result back as a NumPy array

46. Apply PSNR and SSIM to evaluate a processed image against a reference image, and explain what the resulting measures indicate.

To judge how good a processed image is — after compression, denoising, resizing or enhancement — it must be compared with the original reference image using objective numerical measures rather than subjective visual inspection, because human judgement is inconsistent and cannot be automated across thousands of images in a production pipeline. The two most widely used full-reference quality metrics are PSNR, which measures pixel-wise error on a logarithmic scale, and SSIM, which measures the similarity of local structure, luminance and contrast in a way that correlates more closely with how a human viewer perceives image degradation. Together they give complementary views: PSNR catches gross signal corruption while SSIM flags subtle structural damage that PSNR alone might miss.

PSNR (Peak Signal-to-Noise Ratio)

\[ \text{MSE}=\frac{1}{MN}\sum_{i=1}^{M}\sum_{j=1}^{N}\big(I(i,j)-K(i,j)\big)^{2},\qquad \text{PSNR}=10\log_{10}\frac{\text{MAX}^{2}}{\text{MSE}}\ \text{dB} \]

\(I\) is the reference image, \(K\) the processed image, \(M\times N\) the image size, and MAX is the largest possible pixel value (255 for 8-bit). MSE is the average squared difference between corresponding pixels; PSNR turns it into a logarithmic decibel scale so that a smaller error gives a larger number. For example MSE = 25 gives \(10\log_{10}(255^{2}/25)\approx34.2\) dB. Identical images have MSE = 0 (PSNR infinite). Typical values for 8-bit images are 30–50 dB, and the scale is shown below.

SSIM (Structural Similarity Index)

\[ \text{SSIM}(x,y)=\frac{(2\mu_x\mu_y+C_1)(2\sigma_{xy}+C_2)}{(\mu_x^{2}+\mu_y^{2}+C_1)(\sigma_x^{2}+\sigma_y^{2}+C_2)} \]

It is computed on small windows \(x\) and \(y\) taken from the two images. \(\mu_x,\mu_y\) are the mean brightness of the windows (luminance), \(\sigma_x^{2},\sigma_y^{2}\) their variances (contrast), \(\sigma_{xy}\) their covariance (how structure moves together) and \(C_1,C_2\) are small constants that avoid division by zero. The values of all windows are averaged into one score (mean SSIM, often abbreviated MSSIM). Because the comparison is local rather than global, SSIM can detect spatially localised degradation — a blurred corner, a compression artefact in one region — that a single global MSE number would dilute across millions of clean pixels.

What the measures indicate

PSNRSSIM
Range0 to infinity dB−1 to 1 (usually 0 to 1); 1 = identical

Good valueAbove about 30 dB (above 40 dB: hardly any visible difference)Above about 0.9 (above 0.95: very similar)

A processed image with PSNR about 34 dB and SSIM about 0.95 is therefore very close to the reference; a result with PSNR 18 dB and SSIM 0.6 shows clear degradation. Both metrics are full-reference, meaning they require the original clean image for comparison and therefore cannot be used when no original exists — in such cases blind or no-reference metrics like BRISQUE are used instead. In practice the two are reported together: if a denoising algorithm raises PSNR by 3 dB but drops SSIM from 0.96 to 0.88 it may be over-smoothing texture, which is a useful diagnostic that neither metric alone would clearly reveal.

import cv2, numpy as np
ref = cv2.imread("original.png", 0)                       # reference image (gray)
img = cv2.imread("processed.png", 0)                      # processed image, same size

mse = np.mean((ref.astype(np.float64) - img.astype(np.float64)) ** 2)   # average squared difference (float to avoid uint8 wrap)
psnr = float("inf") if mse == 0 else 10 * np.log10(255 ** 2 / mse)      # decibel scale
print("PSNR:", psnr, "dB", cv2.PSNR(ref, img))            # cv2.PSNR gives the same value in one call

from skimage.metrics import structural_similarity as ssim   # scikit-image implementation of the SSIM formula
score = ssim(ref, img, data_range=255)                    # data_range = MAX - MIN of the pixel values
print("SSIM:", score)                                     # 1.0 means identical

47. Explain retina-inspired models and discuss their relevance to image processing and computer vision.

Retina-inspired (bio-inspired) models imitate the way the human retina pre-processes visual information before it reaches the brain, and their key insight is that millions of years of evolution have already solved the problem of extracting useful visual signals under wildly varying illumination and noise conditions. The biological retina does not send raw pixel values along the optic nerve: it adapts to local light levels over a dynamic range exceeding 10 orders of magnitude, removes spatial and temporal redundancy, suppresses noise through lateral inhibition, and splits the signal into two separate channels — one for fine detail and colour, another for motion and transient change. Applying these same principles as a computational pre-processing stage gives computer-vision pipelines that work robustly under difficult lighting, glare, shadows and rapidly changing scenes where conventional histogram equalisation or fixed gain would fail.

Main stages (as in OpenCV's bioinspired Retina model)

  • Photoreceptors: local luminance adaptation, which compresses very bright and very dark regions so that both stay visible (like tone mapping of high dynamic range scenes).
  • Outer plexiform layer (OPL): horizontal cells smooth the signal in space and time, removing noise and acting as a band-pass filter that enhances contours and cancels the average illumination.
  • Parvocellular channel (inner plexiform layer): slow, high-resolution, colour-sensitive path for fine detail and texture; its output is a contrast-enhanced, illumination-corrected image.
  • Magnocellular channel: fast path sensitive to changes over time; its output highlights moving objects and sudden events, and ignores static background.

Relevance

  • Illumination robustness: improves edge and feature detection in shadows, glare or night scenes by adapting locally to brightness, and gives HDR-like tone mapping from ordinary 8-bit images without needing bracketed exposures.
  • Motion and event detection: the magno output is a ready-made motion map for surveillance, tracking and intrusion detection, isolating moving foreground from a static background without the need for explicit background subtraction models.
  • Noise reduction and efficiency: the biological design removes spatial and temporal redundancy before heavier downstream processing, reducing the data volume that subsequent feature detectors or classifiers must handle.
  • Link to learning: the same inspiration appears in convolutional networks (local receptive fields, centre-surround filtering) and in neuromorphic event cameras, which output per-pixel brightness changes rather than full frames, closely mirroring the magno channel's temporal-difference encoding.
import cv2
cap = cv2.VideoCapture("traffic.mp4")
ok, frame = cap.read()
h, w = frame.shape[:2]
retina = cv2.bioinspired.Retina_create((w, h))            # needs opencv-contrib-python; size of the input frames
while ok:
    retina.run(frame)                                     # feed one frame through the retina model
    parvo = retina.getParvo()                             # details + colour, lighting corrected
    magno = retina.getMagno()                             # motion map: moving things appear bright
    cv2.imshow("parvo", parvo); cv2.imshow("magno", magno)
    if cv2.waitKey(1) == 27: break                        # Esc to quit
    ok, frame = cap.read()

Remember: parvo = fine detail and colour (the “what”), magno = motion (the “where is something changing”). The retina model is useful as a pre-processing step before feature detection, tracking or segmentation.

In an exam, mention that the model is bio-inspired: it is not a trained network but a set of spatial and temporal filters whose parameters (such as the adaptation strength and the time constants) can be tuned through the setup function.

48. Explain the purpose of the OpenCV Viz module and describe how it can be used to visualize 3D data.

The Viz module of OpenCV (opencv2/viz.hpp, built on top of the VTK rendering library) is a 3D visualisation tool designed to bridge the gap between computing 3D data and actually seeing it. Ordinary imshow can only show flat 2D images, but many computer-vision results — point clouds from stereo reconstruction, camera poses recovered during calibration, sparse maps built by visual SLAM and trajectories from visual odometry — are inherently three-dimensional and must be inspected from different angles to verify correctness and spot systematic errors such as drift or misalignment. Viz provides an interactive OpenGL-backed window in which these results can be displayed, rotated with the mouse, zoomed and animated frame by frame, all without leaving the OpenCV ecosystem or writing custom rendering code.

How it is used

  1. Create a window with viz::Viz3d, which initialises the rendering context and sets up mouse and keyboard callbacks for interactive navigation.
  2. Create widgets — the displayable objects — choosing from coordinate axes, lines, planes, cubes and spheres, 3D text, images mapped onto planes, point clouds (WCloud), triangle meshes and camera frustums (WCameraPosition), each of which wraps the underlying VTK actor.
  3. Add each widget to the window with showWidget(name, widget); the string name serves as a handle used later to update, reposition or remove that widget without rebuilding it.
  4. Position or animate widgets by assigning a rigid-body pose (cv::Affine3d, which encodes a 3×3 rotation and a translation vector) using setWidgetPose, and control the virtual camera's viewpoint with setViewerPose.
  5. Show the scene: call spin() to block until the user closes the window, or call spinOnce(delay) inside a loop for frame-by-frame animation where each iteration updates widget poses before redrawing.

Typical use: display the dense point cloud from reprojectImageTo3D (Q44) coloured by the original pixel values to produce a textured 3D view, overlay the camera positions found during multi-view calibration as frustum icons so the spatial coverage can be verified, or draw the trajectory of a moving camera in a SLAM pipeline to check for drift. Researchers also use it to visualise estimated versus ground-truth poses side by side, making alignment errors immediately obvious. Note: the module belongs to opencv_contrib, needs OpenCV compiled with VTK (the Visualization Toolkit), and is mainly used from C++ because it is not included in the standard Python pip wheels — Python users typically fall back to Open3D or PyVista for similar functionality.

#include <opencv2/viz.hpp>
using namespace cv;

int main() {
    viz::Viz3d win("3D view");                                  // create the window with a title
    win.showWidget("axes", viz::WCoordinateSystem());           // X (red), Y (green), Z (blue) axes at the origin

    viz::WCube cube(Point3d(-0.5, -0.5, -0.5), Point3d(0.5, 0.5, 0.5),
                    true, viz::Color::blue());                  // cube given by two opposite corners; true = draw edges
    win.showWidget("cube", cube);                               // add it under the name "cube"

    std::vector<Point3f> pts;                                   // fill with 3D points, e.g. from reprojectImageTo3D
    for (int i = 0; i < 500; i++)
        pts.push_back(Point3f(rand() % 100 / 50.f - 1, rand() % 100 / 50.f - 1, rand() % 100 / 50.f));
    viz::WCloud cloud(pts, viz::Color::green());                // point cloud widget
    cloud.setRenderingProperty(viz::POINT_SIZE, 3);             // make points visible
    win.showWidget("cloud", cloud);

    for (int k = 0; k < 360; k++) {                             // simple animation: spin the cube
        Affine3d pose(Vec3d(0, k * CV_PI / 180, 0), Vec3d(2, 0, 0));   // (rotation vector, translation)
        win.setWidgetPose("cube", pose);                        // move the widget named "cube"
        win.spinOnce(10, true);                                 // redraw for 10 ms
    }
    win.spin();                                                 // keep the window open for mouse rotation
    return 0;
}

Why not simply use matplotlib? Viz is integrated with OpenCV types (Mat, Point3f, Affine3d), shows large point clouds smoothly with mouse navigation, and can display camera frustums and trajectories, which suits calibration, stereo and SLAM results. Its limitation is the VTK dependency and the lack of standard Python support.

Typical workflow: compute 3D data (cloud, camera poses), convert it to Viz widgets, add them to a Viz3d window, and call spin() to inspect the scene interactively.

49. Apply YOLO to perform real-time object detection on video frames, describing the major steps from input to output.

YOLO (“You Only Look Once”) detects objects in a single pass of one neural network over the whole image, in contrast to two-stage detectors like Faster R-CNN that first propose candidate regions and then classify each one separately. This single-shot architecture makes YOLO fast enough for real-time video — typically 30–160 fps depending on the model size and hardware — because it amortises the cost of feature extraction across all objects in the scene simultaneously rather than running a classifier hundreds of times per frame. Each video frame goes through the following steps.

  1. Load the model once: network configuration and trained weights (for example YOLOv4-tiny or an ONNX model) and the class names, outside the frame loop.
  2. Read a frame with VideoCapture (camera or video file).
  3. Pre-process: resize to the network size (such as 416×416), scale pixel values to 0–1, swap BGR to RGB and pack into a 4D blob with blobFromImage.
  4. Forward pass: one run of the network produces thousands of candidate boxes (anchors) at multiple scales, each encoding a centre \((c_x,c_y)\), width, height, an objectness score indicating whether anything is present, and a vector of per-class probabilities.
  5. Decode: for every candidate, take the class with the highest score, multiply by objectness to get the final confidence, discard all boxes below a confidence threshold (e.g. 0.5) and scale the box coordinates from the network's normalised 0–1 range back to the original frame size in pixels.
  6. Non-maximum suppression (NMS): because the grid and anchor mechanism typically generates several overlapping boxes for the same object, NMS keeps only the highest-confidence box and deletes every other box whose Intersection-over-Union (IoU) with it exceeds a threshold (commonly 0.4), ensuring one clean detection per object.
  7. Output: draw the surviving boxes with class labels and confidence percentages on the frame and display or save it; the loop then reads the next frame and repeats from step 2.
import cv2, numpy as np
net = cv2.dnn.readNetFromDarknet("yolov4-tiny.cfg", "yolov4-tiny.weights")   # load once, not per frame
names = open("coco.names").read().strip().split("\n")    # class labels, one per line
outs_names = net.getUnconnectedOutLayersNames()           # names of the output layers
cap = cv2.VideoCapture("traffic.mp4")
while True:
    ok, frame = cap.read()                                # ok is False at the end of the video
    if not ok: break
    H, W = frame.shape[:2]
    blob = cv2.dnn.blobFromImage(frame, 1 / 255.0, (416, 416), swapRB=True, crop=False)   # scale, resize, BGR->RGB
    net.setInput(blob)                                    # give the blob to the network
    outs = net.forward(outs_names)                        # the single forward pass
    boxes, confs, ids = [], [], []
    for out in outs:
        for det in out:                                   # det = [cx, cy, w, h, objectness, class scores ...] (0-1 values)
            scores = det[5:]
            cid = int(np.argmax(scores))                  # best class
            conf = float(det[4] * scores[cid])            # objectness x class probability
            if conf > 0.5:                                # confidence threshold
                cx, cy, bw, bh = det[0] * W, det[1] * H, det[2] * W, det[3] * H   # back to pixels
                boxes.append([int(cx - bw / 2), int(cy - bh / 2), int(bw), int(bh)])   # [x, y, w, h] of top-left corner
                confs.append(conf); ids.append(cid)
    keep = cv2.dnn.NMSBoxes(boxes, confs, 0.5, 0.4)       # score threshold 0.5, IoU threshold 0.4
    for i in np.array(keep).flatten():
        x, y, bw, bh = boxes[i]
        cv2.rectangle(frame, (x, y), (x + bw, y + bh), (0, 255, 0), 2)
        cv2.putText(frame, f"{names[ids[i]]} {confs[i]:.2f}", (x, y - 5), cv2.FONT_HERSHEY_SIMPLEX, 0.5, (0, 255, 0), 2)
    cv2.imshow("YOLO", frame)
    if cv2.waitKey(1) == 27: break                        # Esc quits

Choice of model and speed

YOLO comes in several sizes (tiny/nano, small, medium, large), and the choice is a direct trade-off between speed and accuracy measured by mean Average Precision (mAP). A small model with a 320–416 pixel input gives real-time speed on modest hardware at lower accuracy, which is sufficient for counting people or vehicles in surveillance footage; a larger model with a 640 pixel input detects smaller and more occluded objects but needs a dedicated GPU to keep up with video frame rates. Frames can also be skipped, or detection can run every few frames with a lightweight tracker such as KCF or DeepSORT filling in between to maintain object identity across frames. The model weights are loaded only once at startup; only pre-processing, the forward pass and post-processing run per frame, keeping per-frame latency predictable.

50. Analyze how YOLO detects and localizes multiple objects in a frame and discuss the factors that influence real-time performance.

YOLO treats detection as a single regression problem. The image is divided into an \(S\times S\) grid; the grid cell that contains the centre of an object is responsible for detecting it. One forward pass therefore localises and classifies all objects together.

What every cell predicts

  • B bounding boxes, each with \((x,y,w,h)\) (centre relative to the cell, size relative to the image) and a confidence \(=\Pr(\text{object})\times\text{IoU}\) (how sure the box contains an object and how well it fits).
  • C class probabilities for the cell, \(\Pr(\text{class}_i\mid\text{object})\).
\[ \text{score}=\Pr(\text{class}_i\mid\text{object})\cdot\Pr(\text{object})\cdot\text{IoU},\qquad \text{IoU}=\frac{\text{area}(A\cap B)}{\text{area}(A\cup B)} \]

The score tells how likely a box contains a particular class and how well it fits. IoU (intersection over union) compares two boxes \(A\) and \(B\): 1 means identical, 0 means no overlap. It is used both to measure localisation accuracy (a detection is usually counted correct if IoU with the true box is at least 0.5) and in NMS. With \(S=7\), \(B=2\), \(C=20\) the network outputs \(7\times7\times(2\cdot5+20)=7\times7\times30\) values.

From output to final detections

  1. Multiply objectness and class probability to get a score for every box and class.
  2. Discard low-scoring boxes with a confidence threshold.
  3. Apply non-maximum suppression per class: keep the highest-scoring box and remove boxes that overlap it with IoU above the threshold, so each object gets one box.

Because every cell predicts independently, several objects in different cells are found at once; a limitation is that two very small objects in the same cell cannot both be detected in the original design (later versions use anchors and multiple scales to improve this).

def iou(a, b):                                            # boxes as [x1, y1, x2, y2]
    x1, y1 = max(a[0], b[0]), max(a[1], b[1])             # top-left of the overlap
    x2, y2 = min(a[2], b[2]), min(a[3], b[3])             # bottom-right of the overlap
    inter = max(0, x2 - x1) * max(0, y2 - y1)             # overlap area (0 if they do not intersect)
    union = (a[2]-a[0]) * (a[3]-a[1]) + (b[2]-b[0]) * (b[3]-b[1]) - inter
    return inter / union

def nms(boxes, scores, thr=0.4):
    order = sorted(range(len(boxes)), key=lambda i: scores[i], reverse=True)   # best score first
    keep = []
    while order:
        best = order.pop(0)                               # take the strongest remaining box
        keep.append(best)
        order = [i for i in order if iou(boxes[best], boxes[i]) < thr]   # drop boxes overlapping it too much
    return keep
